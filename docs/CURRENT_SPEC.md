# 当前需求与业务规则

本规范取代初稿中的只读 AI、学生归还前人工验收和分阶段开发安排。用户确认的方向是完整业务系统，AI 同时服务学生、实验员、维修人员和管理员，能查询、汇总、推荐卡片及执行已授权的借用申请、照片归还和报修。

## 功能和职责

学生查询设备与预约时间，提交申请；实验员审核并核对实物发放。学生上传照片后直接归还，实验员事后检查，可另建故障工单。故障由实验员核实，影响使用则建立禁借原因，分派维修人员处理，提交验收后由非本维修执行者的实验员验收。多角色按权限并集计算，但不能自行审批、自己维修自己验收或归还他人借用。

AI 首页提供按角色的一键入口。学生查可借设备、本人借还、报修进度；实验员查当前选定实验室借还、故障与统计。所有工具通过 Java 获取当前权限范围的事实，Java 也是所有业务写入入口。对话卡片操作与普通网站操作走相同服务方法。

## 借还规则

一单一台实体设备。申请时不占用时段，批准后占用。时段为左闭右开，比较前统一到毫秒，支持相邻预约。申请最长 7 天、提前最多 14 天；当前界面和业务限制单日开放时段申请，跨日分开提交。开放时间和闭馆日按 Asia/Shanghai 解释，业务时间 UTC 存储。

审批、发放、归还、故障核实、解除限制及启停先锁设备主行，再读最新记录。数据库生成列唯一约束保证同设备至多一个未归还借用，预约唯一约束保证不重复发放。发放窗口为开始前 15 分钟至开始后 30 分钟，且不得越过预约结束或侵占其他有效预约。

归还至少一张本人上传的有效 JPG/PNG 图片。归还记录、图片引用、事件和提醒同事务提交，重复请求幂等。照片是归还凭证，不证明设备已经维修合格。设备有异常可同时提交工单，实验员核实后禁借。

## 工单规则

待核实 → 已核实 → 已分派 → 已受理 → 维修中 → 待验收 → 已关闭。待核实可撤回或驳回；分派后可退回重分派；验收不通过退回维修。记录维修步骤、工时、经办人和时间。

每张确认影响使用的工单各有独立禁借原因。关闭只解除本工单限制，手工停用及其他故障保留。故障核实时将未发放的已批准预约置为失效并通知，不自动复活旧预约或替换设备。借出事实继续保留，不能因工单关闭或预约过期自动归还。

## AI 操作规则

工具白名单包含查设备、查借还、查工单、读工单上下文、查实验室、统计、知识检索、创建预约、本人照片归还和报修。没有审批、发放、停用、维修验收及关闭工单工具。

写入要求本轮明确意图，咨询或否定操作不执行。归还图片为本轮附件，借用目标须唯一、用户明确指定，或模型识别出匹配资产编号。无法确定时返回本人借用卡片。模型输入包含图片；真实图像识别需要相应模型能力，demo 不识别真实图片。

单轮 90 秒、最多 6 次工具调用；Java 再次执行预算和实时权限检查。内部服务密钥识别服务，runId 与短期票据约束本次调用，票据不进入浏览器和模型参数。工具出错不宣称成功；有界重试仅适用于网络模型请求，业务写操作由幂等保证。

## 知识和统计

资料支持文本 PDF、DOCX、TXT、Markdown，文本提取后按片段向量化。资料有版本、适用型号、类别和范围，新版本索引成功并审核后才发布。停用先在业务层生效，检索前过滤发布版本，返回前再核权限。历史引用保留版本快照，权限失效后隐藏历史结果。

利用率分母为统计周期内、设备已建档后的开放时间，扣除停用和维修区间并集；分子为实际借用与剩余可开放时段交集。预约不算使用，未归还截至统计时刻，零分母单独展示。统计包含借用趋势、分类和状态、故障设备分布、工单状态、平均维修耗时及当前逾期。开放规则保存历史生效区间。

## 当前边界

没有采购、耗材库存、财务折旧、IoT、短信、扫码和原生手机应用。学院与专业账户导入、批量预约、复杂跨日开放排班、维修重复工单合并不在当前界面中。文件扫描件需先 OCR。真实模型和向量质量需独立验证。

2026-11-04 交互更新：照片作为归还凭证，不要求视觉模型检验。普通文本模型依据本轮照片存在、明确归还话语与本人借用匹配执行；目标歧义返回选择卡片。未配置 Embedding 使用关键词检索；已配置的向量服务失败时明确报错。

后续确认：移除向量模型配置，知识库统一关键词检索，普通聊天模型通过工具取得资料后组织答案。下一轮简化以开题核心闭环为准，其他删减先形成方案。

最新补充：有视觉能力时发送图片并允许读取设备及故障信息；只在明确不支持图片的响应后兼容为同一模型的文本请求。归还不以识图为前置条件。开题原文第8项已核实要求站内消息，继续保留并增加分账户模块红点；首次建立基线，后续变化亮红点，查看后清除。
