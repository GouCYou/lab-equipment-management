# 毕设功能精简建议

现已重新读取原始开题报告（2026-11-04）。下列早期删减表仅是备选建议：原文明确要求工单核实、分派、受理、维修、验收、关闭，知识来源与版本，多个统计维度及站内消息。不能把这些列为“开题没有要求”。优先精简多角色叠加、完整审计界面、维修费用、复杂日历和生产运维。

原文第6项及技术手段第5项明确写向量化与Qdrant；用户最新选择关键词检索，此处按用户要求实现，论文实现说明需同步反映调整。原文第8项写站内消息提醒审核、归还期限和工单进度，因此保留消息提醒，并新增按账户与模块记录的红点。

此文件为删减建议，除用户明确确认的项目外，不表示已删除其他功能。

## 保留的核心

1. 四角色：学生、实验员、维修人员、管理员。
2. 设备档案：名称、编号、类别、位置、可借/借出/维修/停用。
3. 预约借还：学生申请、实验员审批发放、照片归还、逾期显示、预约冲突检查。
4. 故障工单：报修、指派、维修记录、验收关闭，联动设备禁借状态。
5. AI 入口：查设备、提交申请、查借还、照片加话语归还、查工单、总结统计、查知识。借用卡片与普通页面共用业务逻辑。
6. 简单知识库：少量设备手册摘要，关键词召回后由聊天模型组织带来源的回答。
7. 基础统计：设备数量、当前借出、逾期、维修工单、借用趋势与利用率。

## 建议合并或删除

| 当前内容 | 建议 | 理由 |
| --- | --- | --- |
| 多角色叠加、权限点清单、完整审计页面 | 每账户一个角色，后台仅留账户与实验室分配；审计记录留在后台即可 | 演示四种职责即可，界面不需要完整企业权限产品 |
| 七步工单流与多种退回分支 | 简化为待处理→已指派→维修中→待验收→已完成 | 保留报修、负责人、维修结果、验收和设备状态联动 |
| 维修费用累计 | 已移除，保留工时 | 简化维修记录，保留工时和验收流程 |
| 独立消息中心、已读批量操作、每日去重提醒 | 工作台显示待办与逾期即可 | 减少一套独立模块 |
| 知识多版本、审核发布、索引任务与重建 | 单份资料新增/修改/启停，保存后可查 | 三到五份资料足以展示检索增强 |
| 多个饼图、故障分布、复杂维修效率样本 | 四个指标卡、一张趋势图和利用率表 | 指标更容易讲清楚和复核 |
| AI 工具执行工作区、耗时等技术详情 | 默认隐藏或移除，保留答案、来源和业务卡片 | 用户关注业务结果 |
| 复杂开放日历、跨日排班 | 固定每日开放时间，继续单日预约 | 避免扩展成排班系统；不再补闭馆日历界面 |
| 批量导入、扫码、IoT、采购、耗材和财务折旧 | 不增加 | 超出设备借还和故障处理主线 |
| 生产多实例、自动备份轮换、监控、完整多平台部署 | 只保证本机一键运行，其他留为展望 | 减少与毕业演示无关的运维工作 |

## 已完成的简化

模型设置只保留一个聊天模型，移除向量模型配置。知识解析保留文本片段，查询按关键词匹配，不产生或请求向量。照片作为归还凭证，普通文本模型无需看到图片内容。

“检索增强”不必等同于“向量检索”：关键词检索得到资料，再与问题一起交给聊天模型，也能展示有依据的回答。论文实现章节应如实描述；如果开题正文具体承诺了向量检索，应将实施调整向导师说明，而不能把关键词方案写成已完成向量检索。

精简时继续保留本人借用、实验室范围、预约冲突、设备占用一致性，避免演示中发生重复发放或替他人归还。学生照片归还保持直接完成，不增加人工前置验收。
