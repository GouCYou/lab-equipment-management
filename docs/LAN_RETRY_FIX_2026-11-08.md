# 局域网重试与模型请求修复

之前使用 localhost 验证，遗漏了局域网 HTTP 与 localhost 的浏览器差异。前端 post() 默认参数直接调用 crypto.randomUUID()，在非安全上下文中不可用时会在网络请求发出前抛错。ActionHost 的预约/归还等表单存在相同调用。现统一通过 requestId()，在缺少 randomUUID 时使用 getRandomValues 生成标准 UUID v4。

两类失败需区分：此前原始供应商响应确有 HTTP 429/free_campaign_global_limit；局域网按钮未发请求则是前端兼容缺陷，并非供应商限流。本轮同配置最小请求返回 HTTP 200，随后从 http://192.168.31.102:5188 登录并点击失败会话的重新生成，数据库记录 19:43:02 至 19:43:12（北京时间）执行成功，浏览器显示真实查询结果与设备卡片。

自动重试采用参考项目的上限和退避策略：首次请求外最多 4 次，暂时性 429、502/503/504、连接超时/网络错误按 2、4、8、16 秒等待，Retry-After 支持秒数和 HTTP 日期，上限 60 秒。401、403、明确额度耗尽不重试；Agent 整轮 90 秒预算继续生效。仅重试模型 HTTP 调用，不重新执行已完成的业务工具，不回退预置回答。重试次数、状态码和等待秒数记录到 AI 服务日志，不记录密钥或请求正文。
